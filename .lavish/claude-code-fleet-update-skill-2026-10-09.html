If you invoke it inside Claude Code

That session coordinates the update and stays running. It audits the fleet, installs an updated binary if needed, and restarts other eligible agents one at a time. Its own loaded version changes only after it exits and starts again.

Without an independent controller, it finishes the report and learning pass, then gives you its exact saved-conversation resume command and any background-service recovery instructions. You perform that final exit/resume. A separately authorized existing agent can handle the final restart instead; the Skill does not create an agent or a detached self-restarter automatically.

How the improvement compounds

The running agent makes the edit. After a verified fix or your explicit workflow correction, it updates the relevant rule and records the evidence. You do not need to ask it to save the same lesson separately.

New invocations re-read the shared files. Codex and Claude Code therefore receive the same improvement.

A run with no new durable lesson leaves the rules unchanged and records that review. Temporary process IDs, ports, session IDs and secrets are not learned as permanent instructions.

No background listener was installed. The learning pass operates while this Skill or its related follow-up task is active.

What it does during an update

Audit and restart

Check actual loaded versions, exact conversation identities, original launch options and live jobs. Skip agents already current. Restart sequentially in the same terminal, preserving the conversation and settings; verify each target before continuing.

Restore background work

Name the precise service and its original directories/options. Check for survivors, restore only missing repeatable services, and verify one ready instance. Firstmate uses its existing startup and monitoring recovery. A saved conversation does not recreate live jobs.

Persist and validate lessons

Before a changed rule, save the previous Skill and references under revisions/. Edit the source, increment the revision, record the trigger/evidence and validate the diff. Restore the prior version if validation fails. A lesson cannot grant new permissions or change unrelated Skills.

What actually changes on disk

The agent edits the reusable procedure. This is a required instruction in the Skill, carried out through the agent’s normal file-editing tools during the active task.

Three maintained files, plus rollback copies

SKILL.md: the operational rule used on future runs, and its revision number.

references/lessons.md: durable lessons with their conditions and evidence; read on every invocation.

references/revisions.md: the trigger, change and validation record.

revisions/: pre-edit .bak copies, allowing a failed edit to be rolled back.

A verified new lesson or explicit reusable correction leads to a narrow edit and validation. A temporary instruction stays within the current run. No new durable lesson means a review receipt with unchanged rules and revision.

Example: your question about self-restart revealed that the agent doing the update must stay alive. Revision 1.2 now protects that session and provides a final manual restart step unless an independent controller is authorized.

This mechanism relies on the executing agent following the learning pass and having file access. The Skill requires a checked learning receipt, so it cannot honestly claim persistence when the edit was not made.
